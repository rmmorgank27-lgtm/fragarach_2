# macOS Console Read and Write Boundaries

The native target links system SQLite through `CSQLite`. `SQLiteReadService` opens the operator-selected file with `SQLITE_OPEN_READONLY | SQLITE_OPEN_URI | SQLITE_OPEN_NOMUTEX`, verifies `sqlite3_db_readonly`, enables `query_only`, and permits only fixed bounded `SELECT` statements. It retains no persistent copy.

`ProcessBridge` invokes only the explicitly configured Python executable with `PYTHONPATH` fixed to the explicitly configured repository. `fragarach_ii.operations_cli.v1` prevents accidental invocation of an incompatible installation. `ArgumentBuilder` constructs non-secret arrays for acquisition, import, validation, verification, and backup. The child inherits a credential only through its environment. Output is filtered before publication.

Python remains responsible for filesystem writer locking, canonical instrument registration, transactions, raw evidence, canonical merge, provenance, lane state, validation summaries, integrity, and backup verification. The exact read boundary is eight tables. The Swift layer has no write-capable SQL and no second ingestion implementation.
